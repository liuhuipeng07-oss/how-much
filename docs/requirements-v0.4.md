# 值多少？V0.4 产品需求与交付范围

产品名称：值多少？  
Slogan：今天的你值多少？  
本轮定位：用像素角色记录拥有的物品，用轻松投票讨论想买的东西，用闲置背包整理准备告别的旧物。

## 一、确认的产品方向

核心主线：**想拥有 → 买前问问 → 自己决定 → 已拥有 → 角色装备 → 闲置展示 → 确认转出。**

投票是互动特色，不是强制审批。票数不控制购买，不生成“必须购买”的结论。
资产用于统计和展示。闲置先做转让意向展示，暂不承接支付、订单、撮合、收款、物流。
“等等”参考中的审批群、公开广场、频道、围观与人数/时间截止，不全部照搬进本轮。

## 二、信息结构

保留五个主导航：首页 / 世界 / 资产 / 成长 / 我的。

| 页面 | 职责 | 本轮调整 |
| --- | --- | --- |
| 首页 | 角色、当前总值、今日变化、添加资产 | 直接展示财富天气，增加买前问问/闲置背包入口 |
| 世界 | 分类场景、拥有的资产和装备 | 保持已有能力 |
| 资产 | 分类、录入、修改、装备、归档/恢复 | 增加想买/准备告别入口 |
| 成长 | 收入、历史快照、未来模拟 | 保持已有能力；算法仍为现有简化模型 |
| 我的 | 外观、角色名片、分享隐私 | 保持已有能力 |
| 买前问问 | 愿望列表、状态筛选、创建入口 | 新增 |
| 创建愿望 | 商品名称、分类、预算、理由、替代品 | 新增 |
| 愿望卡 | 单选投票、结果、决定、确认入库 | 新增 |
| 闲置背包 | 从资产选择、期望价、成色、备注、撤回/转出 | 新增 |

## 三、买前问问

### 3.1 创建愿望

- 名称：必填，最多40字。
- 分类：数码、收藏、车辆、会员、其他。
- 预算：必填，人民币非负金额，保留两位小数。
- 购买理由：必填，最多300字。
- 替代品：选填，最多300字。
- 新建愿望不影响资产总值、成本和装备。
- 图片、商品链接、留言讨论列入后续版本，不作为本轮已实现能力。

### 3.2 投票与状态

选项：买！值得拥有 / 等等再说 / 这次不买。

- 单选，允许改票；同一设备仅保存最新选择，不重复累加。
- 状态为“问问大家”时可投票，先等等/这次不买时暂停投票。
- 未入库的愿望可重新开启；已入库的愿望到资产页管理。
- 不自动把预算或“不买”的票折算为省钱金额。
- 最终决定由发起者作出；票数不会自动执行任何资产操作。

### 3.3 确认买了

用户填写实际支付价格，再确认“已经买到”。
创建资产：成本=实际支付金额、初始估值=实际支付金额、今日变化=0、默认装备。
愿望记录对应资产ID和入库状态；重复操作不创建重复资产。
入库只是记录用户已发生的购买，不扣除现金余额，也不代为付款。
当前价值后续可在资产页单独修改。

## 四、闲置背包

本轮支持从仍在持有的数码、收藏、车辆中选择。
填写期望转让价（0元表示赠送）、成色说明（必填，最多100字）、备注（选填，最多300字）。

| 状态/操作 | 资产统计 | 人物装备 | 闲置记录 |
| --- | --- | --- | --- |
| 放入闲置背包 | 不变 | 不变 | 展示中 |
| 修改期望价 | 不改变估值 | 不变 | 更新记录 |
| 撤回 | 不变 | 不变 | 已撤回 |
| 确认物品已转出 | 归档、不再计入 | 移除 | 已转出 |
| 在资产页恢复资产 | 恢复统计 | 沿用现有恢复规则 | 不自动重新展示闲置 |

同一资产只保留一条闲置记录；重新放入背包更新该记录。
本轮不提供编辑表单；如需修改期望价/成色，可撤回后重新填写。
独立归档资产后，闲置卡提示先恢复资产；禁止再次确认转出，允许撤回展示。
本轮不记收款、不生成收益，不做宠物、金融资产和数字资产转让。

## 五、像素风与互动

保留原创像素人物、发色/服装选择、奶油纸张、森林绿、金币黄、粗边框与阶梯阴影。
愿望背包使用金币色卡片，闲置背包使用浅绿色卡片。
新增像素背包装饰、按压位移、投票选择弹跳与分段进度条动效。
沿用首页人物互动、签到、世界探索，不重新设计整套角色。

## 六、数据与真实联机边界

本次交付是 **V0.4 本地可运行体验版**。没有部署云数据库或多人投票服务。

| 数据 | 存储键 | 说明 |
| --- | --- | --- |
| 愿望卡 | purchaseWishesV1 | 预算、理由、状态、示例票、本人选择、关联资产ID |
| 闲置记录 | idleListingsV1 | 资产ID、期望价、成色、备注、展示状态 |
| 已有资产等 | 沿用现有键 | 保留数据，初始化新功能不覆盖已有个人档案 |

首次进入愿望背包展示两张明确标注的示例卡，其中票数为预设演示。
自己新建的卡从0票开始。清空的新列表不会自动重建示例。
微信原生分享只分享体验预览标题与预算，落地页明确提示无法读取好友本机愿望、不能收集跨设备票数。
闲置只保存在本机，不显示虚构买家、询问人数或曝光数，不宣称已向公众发布。

正式联机版本需要另外实现：用户登录与权限、云端愿望/投票/闲置数据、唯一投票约束、分享ID读取、内容治理与本人操作校验。
此前自动行情、名片导出图片、专属角色公开页仍未在本轮补齐。

## 七、验收路径

1. 导入现有小程序，首页看到人物、总值、财富天气和两个背包入口。
2. 创建“旅行相机”愿望，预算3299元，理由“周末旅行拍照”；确认总资产不变。
3. 投“买”，再改投“等等”；确认总票数仍是1票。
4. 选择“先等等”；确认投票暂停，可重新开启。
5. 实际支付填写2999元，确认买了；愿望变为已拥有，总值增加2999元，配件可见。
6. 重复确认不重复入库，关闭重开后记录保留。
7. 闲置背包选择相机，填写期望价2000元和成色；确认总值不变。
8. 撤回后资产仍在；重新展示后确认转出，总值减少相机当前估值，配件移除，资产进入归档。
9. 分享预览到好友端应显示本地体验提示，不出现“已参与真实多人投票”的误导。
10. 原有资产、角色、收入和快照仍可读取。

本地验证：`npm.cmd test`、`npm.cmd run check`。
其中页面测试使用微信API桩验证表单→投票→入库→闲置→转出流程，不代替手机实机验证。
